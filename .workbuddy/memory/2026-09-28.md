## 文件传输闪退根因实锤 (用户截图错误弹窗定位)
- 用户运行加固版后弹出错误弹窗(证明 SafeApplication/sys.excepthook 防护生效, 闪退变可见错误), 弹窗 traceback 直接给出根因:
  `AttributeError: 'FileTransferDialog' object has no attribute 'lbl_remote_path'`
  at `_on_remote_drive_changed` (585) <- `_refresh_remote` (739)。
- 根因链: `_build_ui()` 创建远程驱动器下拉框时**先 connect `currentIndexChanged` 再 addItem**; PyQt5 中首条 addItem 立即触发 currentIndexChanged 回调 → `_refresh_remote` → `self.lbl_remote_path.setText()` 而该标签在 3 行之后才创建 → AttributeError。**PyQt5.5+ 槽函数未捕获异常默认 qFatal/abort 整个进程** → 即用户"一开文件传输必闪退"的确定性崩溃。之前所有 try/except 都包不住——异常发生在 Qt C++ 信号分发内部, Python 层 try/except 无法拦截(除非设 sys.excepthook, 这正是加固版能弹窗不崩的原因)。
- 修复 (gui/viewer_window.py): ①`cmb_remote_drive` 改为**先 addItem 再 connect**(加注释说明顺序不可反); ②`_refresh_remote` 增加 `hasattr(self,'lbl_remote_path')` 防御守卫。本地驱动器下拉无此问题(`_update_local_drives` 全程 blockSignals)。
- 验证: 不设 excepthook 的裸进程实例化 FileTransferDialog + 调 `_on_remote_drive_changed(0)` → `FT_DIALOG_OK` EXIT=0(旧代码此场景必 abort); py_compile 通过。
- 经验教训(重要): PyQt5 中"connect 后立即 addItem/setValue 触发信号回调"是闪退高发模式, 控件初始化必须先填数据后连信号, 或 blockSignals 包裹; 槽函数异常在 C++ 信号分发内, Python try/except 拦不住, 全局 sys.excepthook 才是兜底。

## 全面代码梳理: 无法操作/连不上/卡顿 七处根因修复 (2026-09-30)
系统通读 controlled/controller/input_control/protocol/config/network/screen/screen_broadcaster/clipboard_win 后定位并修复:
1. **[无法再次连接/经常连不上] accept 循环韧性** (controlled.py): 原 `except OSError: break` —— Windows 下客户端握手期异常断开会让 accept() 抛瞬时 OSError(WinError 10053), 一次即**永久 break 掉监听循环**, 之后再也连不上。改为: `not self.running` 才 break, 否则记日志+sleep(0.05)+continue。
2. **[无法再次连接] 死连接占满名额** (controlled.py): 认证后 socket **无 keepalive/超时**, 客户端崩溃/断网(半开连接)永久占用 _clients, 满 max_clients(5) 后拒绝一切新连接。修复: `_set_keepalive()`(SO_KEEPALIVE + Windows SIO_KEEPALIVE_VALS(1,10000,3000)); `_message_loop` 改用 `select.select([conn],[],[],30)` 空闲检测, 30s 无数据(主控端5s心跳)即回收; select 超时回收而非 socket.settimeout, 避免 sendall 超时破坏 TCP 帧。
3. **[卡顿] 每帧写日志** (controlled.py safe_send): 原每收/发一条消息写 2 行文件日志, 屏幕帧 30fps 时 = 每秒 60 次文件打开! 已删除逐条日志(仅保留失败日志)。
4. **[卡顿] 慢客户端阻塞整个广播** (screen_broadcaster.py): 原捕获循环对每个订阅者同步 sendall, 一个慢/卡客户端会拖垮所有客户端。修复: 逐客户端帧锁 `_sub_locks`, 用 `acquire(blocking=False)` 非阻塞——上一帧没发完就丢本帧(不排队), 捕获循环永不被慢客户端阻塞。
5. **[无法操作] DPI 坐标错位** (main.py + input_control.py): 进程非 DPI 感知时 SetCursorPos/GetSystemMetrics 用缩放坐标, 与 mss 物理分辨率错位 → 高 DPI 下鼠标点不中/像失效。修复: main.py 建 QApplication 前设 `Qt.AA_EnableHighDpiScaling`+`AA_UseHighDpiPixmaps`(Qt 将进程设 Per-Monitor DPI 感知); controlled.py __main__ 独立运行时 `SetProcessDPIAware()`。input_control.mouse_move 改用 `SendInput(绝对坐标, 归一化 0..65535 相对主显示器)` 替代 SetCursorPos(更可靠, 失败回退)。
6. **[连不上] 端口漂移破坏发现** (config.py + controlled.py + main.py): 原 UDP 发现端口 = TCP端口+1, TCP 因占用自动漂移(7788→7789)后控制器仍广播 7789 且直连 7788 → 全失败。修复: config 新增固定 `DISCOVERY_PORT=7789` + `get_discovery_port()`; 被控端 UDP 固定绑 7789(带 try/except), 主控端广播到 7789; `_find_available_port` 只检 TCP。
7. **[小bug]** (config.py add_history): 原 `pop(i)` 后又 `history[i]` (索引已错位) → 改为先取 item 再 pop/insert。
